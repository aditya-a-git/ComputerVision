# Dataset provenance and licensing

The versioned export comes from datasets/rdd2022.ndjson at baseline 3122e28. Its metadata credits Arya et al., *RDD2022: A multi-national image dataset for automatic road damage detection*. The export contains 38,383 image references and 61,075 boxes. The verified split contains 30,707 train and 7,676 validation images, including 12,658 total negatives. Original IDs 0, 2, 3, 4, 6 map to model IDs 0–4 in that order. Their respective box counts are 10,617, 26,190, 5,850, 6,544 and 11,874. Block crack and repair have no examples. The upstream RDD project identifies its image license as CC BY-SA 4.0. Check the terms for the particular copy you obtain. [RDD source and citation](https://github.com/sekilab/RoadDamageDetector)

Signed export URLs carry their own expiry. The observed value 1796214600 is 2026-12-02 12:30 UTC. Servers can reject requests earlier. The preparer checks each expiry, handles HTTP rejection and never writes URL signatures to derived metadata. The implementation run retrieved and decoded all 124 selected demonstration images.

For an official original-image archive, provide a verified export filename to original relative path crosswalk using `--local DIR --crosswalk mapping.json`. Each entry requires path, width, height, sha256 (original image bytes) and labels_sha256 (the SHA-256 of compact JSON encoding the list [split, normalized remapped boxes]). Produce that crosswalk only after independent identity and annotation reconciliation, for example by comparing an already verified export image to the original and checking the annotation overlay. Retain the crosswalk provenance locally. Dimensions or similar filenames alone cannot establish identity. Unverified entries should be omitted. No alternative HF mirror was assumed compatible. Original labels and CARD labels are never interpreted as export model IDs. [Hugging Face Datasets](https://huggingface.co/docs/datasets/loading)

CARIAD CARD Germany Batch 1 is gated and tagged CC BY 4.0. Inspected revision 9de445059992f5af42aafa8fdbcc156dc7b7816a exposed individual JPG, TXT, NPZ and trajectory files. The official SDK uses cam_1 as left, cam_0 as right and camera-space points for depth projection. The explorer matches the same sequence and exact filename timestamp, undistorts left RGB using camera_infos and projects with the same intrinsic matrix. It retains the nearest positive optical-axis depth per pixel, in metres. Stereo association refers to recorded timestamps. Physical exposure synchronization was not independently measured. Real CARD class names and any alignment to RDD require further verification. The SDK small-samples list inspected referenced other batches, so the CLI selects directly from the requested batch listing.
