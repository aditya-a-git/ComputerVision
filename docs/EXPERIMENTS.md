# Reproducing the experiments

Follow the preparation, training, validation and comparison commands in README. The demonstration uses seed 42, eight epochs, a batch of eight, CPU and YOLO11n at 320 pixels. It uses 100 annotated-or-negative training images and 24 disjoint validation images. Splits are inherited from the export. Drive-level independence is unknown. The best epoch uses validation feedback, so these results are exploratory validation measurements.

scripts.evaluate uses Ultralytics validation on the reserved split. scripts.compare verifies the selected image hashes, constructs a Hugging Face experiment manifest and runs seven pipelines on the identical ordered images. Darkness intensity is 0.65. Both RGB views have the same pixel coordinates. The secondary pass uses a grayscale CLAHE transform. A brightness, contrast and Laplacian-variance heuristic weights each view. Fusion greedily pairs highest-IoU same-class boxes at IoU ≥ 0.5, uses reliability times detection score for coordinates, and discounts scores for unmatched evidence. The proxy shares its input and trained detector with RGB.

The comparison keeps scores from 0.001, sorts per class, matches at most one detection to each annotation per image and IoU threshold, then averages interpolated precision at 101 recall points. mAP averages classes with annotations and uses ten IoU thresholds from 0.50 to 0.95. Precision, recall, F1, FP and FN use score ≥ 0.25 at IoU 0.50. This simple evaluator does not support crowd regions. Ultralytics and paired-comparison values can differ with resolution, preprocessing, confidence filtering and AP implementation.

After one warm-up call, each timed comparison frame includes local image decoding, the specified transform, reliability processing, executed detector branches and fusion. Exports, charting, UI and disk write time are excluded. FPS is processed frames divided by measured total seconds. Per-frame latencies, provenance and hashes are in report.json. App frame timings cover the selected pipeline on an already decoded image. Temperature and stream health are simulated.

The saved measurement folder includes the actual validation report, CSV summary, trainer history, acquisition manifest and native Ultralytics result. New runs use a fresh timestamped directory under runs/comparisons. Small sample size, class imbalance and weak localization limit inference about relative model quality.

## Six-condition environment benchmark

Use the reproduction commands in README. The separate `scripts.environment_benchmark` entry point uses prepared original-resolution images from `scripts.prepare_rdd`. It checks the prepared image hashes and verifies the remapped boxes, image dimensions and validation membership against the versioned RDD export. From a seeded shuffle it reserves one annotated image and one genuine negative, then fills up to the requested limit (2–256). A preparation lacking either group produces an error. All conditions use that one ordered subset, checkpoint, detector size and settings. Daylight always runs first. Vibration applies the existing diagonal motion-blur kernel. The noise and rain transforms restart the seeded generator on each frame.

Metrics use the paired evaluator described above. Global precision, recall and F1 pool counts across classes at score 0.25. AP uses ranked predictions down to 0.001 and detector NMS IoU 0.70. Classes without ground truth have undefined AP and drop out of the macro average. FP on negative images still count. Undefined aggregate ratios serialize as JSON null or blank CSV cells. Delta columns subtract daylight from each condition. Percentage latency change uses daylight mean pipeline latency as the denominator.

After one untimed warm-up at the chosen resolution, synchronous CPU pipeline timing starts before image decode and ends when boxes return. Detector timing covers RGB-to-BGR conversion, Ultralytics preprocessing, forward pass, NMS and conversion to Python boxes. It is a detector-call measurement. Pipeline time also covers decode and the perturbation. Evaluation, visualization, serialization and UI time are excluded. Processed FPS equals frame count divided by summed pipeline seconds. Timing varies with CPU load and image dimensions.

A unique run under `runs/environment_benchmarks/` holds config.json, manifest.json, predictions.jsonl, per_sample_metrics.csv, timings.csv, summary.csv, summary_metrics.json and figures/. Streamlit reads the saved summary. Select one annotated or one negative preview to inspect input pixels, branch predictions at the operating threshold and ground truth.

## Reading fusion and controller runs

The quality estimate averages grayscale brightness balance, clipped standard deviation / 48 and clipped Laplacian variance / 120. Health multiplies the estimate. Positive active weights are normalized to shares. These are heuristic scores. Matched candidates share a class and meet the greedy one-to-one IoU rule. Coordinates use quality × health × confidence and the output score is the reliability-weighted mean. Unmatched candidates are scaled by their branch share. A score below the final cutoff drops the candidate. A single eligible branch keeps its detector scores unchanged. Trace indices refer to the per-branch prediction arrays in the detection JSON. The trace begins after detector NMS and score filtering.

An edge step runs the existing controller once. At 70°C it requests two 320 px passes, at 85°C a single best-view 320 px pass. The normal two-pass route uses 640 px. Recovery boundaries are 80°C and 65°C and a thermal level persists for at least two updates before switching. One connected stream immediately requests a single pass, two disconnected streams request zero. Quality can also make a connected view ineligible. The timeline distinguishes the requested route from executed branches. A missing checkpoint still allows controller observations.

The first ramp step uses the start value. Subsequent steps add the configured increment and clamp to the maximum. Pause retains progress, reset clears the history and controller, and manual temperature steps allow testing cooling and oscillation. Mode summaries group measurements from the last 100 steps by controller route. Latency starts on a decoded frame and ends after view preparation, detection and fusion/filtering. Branch timings measure individual CPU detector calls. No-inference steps have no detection latency or FPS. Frame counts qualify every percentile, and the virtual temperature is independent of the host machine.
